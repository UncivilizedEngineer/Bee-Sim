# Hive thermal / humidity / colony visualizer (web build)

An interactive 3D viewer for a lumped-node thermal, humidity and colony simulation of a 10-frame Langstroth hive. It shows:
- a temperature or RH field interpolated between model nodes, including stratified air layers and the cluster core and mantle,
- condensation films on inner surfaces and under the outer cover,
- energy-flow arrows,
- synced charts, with a time scrubber that plays back over 24 h or 365 d,
- cross-section planes and transparency controls.

The model is uncalibrated and meant for comparing housings, so treat absolute numbers as order-of-magnitude.

Showcase data:
- Edmonton, 1 deep, baseline wooden hive, one year, sampled every 3 h (model v1.5 export).
- One winter day (Edmonton, January, 24 h at 10-min steps).

## Use
- Open `index.html` through any static server. Pages works out of the box; `file://` does not, because ES modules and fetch need http.
- URL parameters:
  - `?embed=1` hides the side panels; the ☰ button opens the controls.
  - `?run=<id>` picks the scenario.
  - `?k=<step>` sets the start step.
  - `?geom=parametric` swaps in the placeholder geometry.
- ⛶ toggles full screen. On narrow screens the layout stacks vertically.

## Update the data
The site is generated by the source project (`hive_viz/`, outside this repo). After the model export is regenerated:
```
/workspace/hive_viz/tools/refresh_web.sh          # rebuilds data/, app.js, vendor/, cad/hive.glb
cd /workspace/hive_viz/web && git add -A && git commit -m "Refresh data" && git push
```
`WEB_SCENARIO`, `WEB_STEP` and `WEB_DAY` choose the scenario and the downsampling.

## Files
| File | What it is |
|---|---|
| `index.html` | page (import map points `three` to `vendor/`) |
| `app.js` | viewer bundle, Three.js external |
| `vendor/three.module.min.js` | Three.js r186, MIT (`vendor/THREE_LICENSE`) |
| `cad/hive.glb` | hive parts from the CAD model (STEP → STL → GLB) |
| `data/official/*.json` | model export, schema 1.0, downsampled |
| `data/*.json` | 24 h interim run |

Data is loaded lazily: each scenario is fetched only when it is selected.

## Enable GitHub Pages
1. Create a GitHub repo and push this folder to `main`.
2. In the repo, go to **Settings → Pages**. Set **Source** to *Deploy from a branch*, choose **main** and **/ (root)**, and save.
3. The site appears at `https://<user>.github.io/<repo>/`. `.nojekyll` is included so the files are served as-is.
